# Архитектура

Вертикальная Android-игра, Godot 4, бой 5 на 5, камера сбоку и сверху. Полный город и RPG-экраны будут каркасом. Первый играбельный кусок — бой.

## Кто что считает

Сервер авторитетен для аккаунта, экономики, прогресса и награды. Клиент не сообщает «я победил, выдай золото».

Сейчас есть предварительный расчёт `POST /LunexGame/battle/sim`. Он возвращает лог и `"reward_granted": false`. Отдельной ручки награды нет.

Аккаунты: `POST /LunexGame/auth/guest`, `register`, `login`, `bind`. Профиль `GET /LunexGame/me`. Отряд `PUT /LunexGame/me/formation` принимает пять id и игнорирует присланное золото. Хранилище — память процесса, поле `persisted: false`. Восстановление почты — `501`, письма нет.

Тот же лог сцена проигрывает. Ближние бойцы получают события `move` и подходят к цели. Дальние бьют с места. Это не навмеш и не физический движок.

Две модели на первом тесте повторяются на десять бойцов. Пока моделей нет, сцена ставит капсулы `TEMP_A` и `TEMP_B`.

## Формация

Слоты 0 и 1 — фронт, 2, 3 и 4 — тыл. Роли: танк, боец, стрелок, маг, целитель. Танк и боец сближаются. Остальные остаются на дистанции, если цель уже в радиусе.

## Папки

| Путь | Назначение |
|---|---|
| `client/` | Godot |
| `server/` | API |
| `admin/` | Game Studio, появится на этапе 06 |
| `infra/` | только свой compose, без чужих проектов |
| `docs/` | аудит и решения |
| `.github/workflows/` | ручные проверки |

Стек по умолчанию: Godot 4, GDScript, Python, FastAPI, PostgreSQL, позже React для админки. Postgres в этом коммите не поднималась.
